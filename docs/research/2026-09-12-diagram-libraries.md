# Diagram and Flowchart Library Options for the Canvas

Research date: 2026-09-12. Facts below were checked against live sources on this date, not from memory.

## Recommendation

Use **React Flow**, the open-source library published as `@xyflow/react`, at **https://github.com/xyflow/xyflow** (docs at reactflow.dev). In plain terms, React Flow is a free toolkit for placing boxes on an endless, zoomable page and drawing lines between them that automatically stay attached and re-route when a box moves. That "stay attached" behavior is the single hardest part of a FigJam-style tool to get right, and React Flow already does it well. It does not include the shape palette (rectangle, diamond, sticky note) or undo history, so we would still design and build the drawing experience ourselves on top of its engine. The tradeoff: a rival tool called tldraw (tldraw.dev) already ships that whole experience, polished and free to develop with, but it changed its terms in late 2025, so shipping it in production now needs a paid license (about $6,000 a year, reported) or a permanent watermark, and fitting our components inside its canvas is a bigger rework than the reverse. React Flow costs nothing, carries no licensing risk, and fits how our app is built.

## What we verified, and how

**React Flow / xyflow.** Fetched github.com/xyflow/xyflow directly: MIT, 38.4k stars, an active monorepo (React Flow plus Svelte Flow). Confirmed `@xyflow/react` 12.11.6 shipped about 10 days ago. Bundlephobia's own data: 59.9 KB gzipped, the lightest DOM-based option here. No shapes ship built in; official docs point to a "Shapes" example for building rectangles, diamonds, and ellipses as custom nodes. Connector labels and automatic re-routing are native, with keyboard focus, deletion, and ARIA roles documented. Showcases: reactflow.dev/showcase and reactflow.dev/pro/case-studies/carto-case-study.

**tldraw.** Fetched github.com/tldraw/tldraw: 50.3k stars, 6,554 commits, clearly active. Per tldraw.dev/community/license: free in development, but production needs a license key; a discretionary free "hobby" license requires a permanent watermark and targets non-commercial projects. The reported $6,000/year price comes from third-party reporting (BigGo Finance, a Hacker News thread on the September 2025 change), not a public tldraw figure, plus a 100-day trial. Docs confirm shapes, sticky notes, auto-rerouting arrow "bindings," labels, undo/redo, and SVG/PNG/JSON export are built in, and custom shapes can hold arbitrary React via a helper called HTMLContainer. Its blog documents ClickUp rebuilding its whiteboard on the SDK (tldraw.dev/blog/clickup).

**Excalidraw.** Fetched github.com/excalidraw/excalidraw: MIT, about 130k stars, updated as recently as September 11, 2026. Bundlephobia: 352.7 KB gzipped. Shapes, connector binding, labels, undo/redo, and export are mature and built in. The catch, from its own rendering docs: it draws onto an HTML canvas bitmap with RoughJS, rather than giving each shape a real DOM element, so there is no supported way to drop an interactive React frame onto its canvas as a shape; the only sanctioned outside content is an "Embeddable" iframe. Open issues (#9186, #8923) show React 19 support is informal, not a hardened guarantee.

**Quickdraw.** Checked tryquickdraw.com and github.com/quickdrawjs/quickdraw: MIT, built explicitly as a free, no-watermark response to tldraw's license change, with React, React Native, and plain JS packages. Young (452 stars, self-described as "the youngest" whiteboard SDK) with a small reported bundle (about 25 KB gzipped, per its own comparison page, so treat that as a vendor claim). No independent shape-binding check or production showcase was found.

**JointJS.** Fetched github.com/clientIO/joint: MPL-2.0 core, 5,272 stars, a commit within 8 days. Per jointjs.com/license and a ComponentSource listing: the free core includes a full shape library and an industrial-grade routing engine, the most sophisticated connector routing of any candidate here; paid JointJS+ runs roughly $3,400 and up per developer. It predates React, so hosting our frames means an SVG `foreignObject` or an HTML overlay; a Synergy Codes article and JointJS's own forum both note React content inside a `foreignObject` can render incorrectly under certain transforms, a real risk for us.

**Also considered and set aside:** GoJS (commercial, ~$3,995/developer, canvas-bitmap rendering, so it cannot host live React content without manual overlays), Konva/react-konva (a raw drawing surface, no built-in shapes or connectors), maxGraph (actively maintained Apache-2.0 successor to mxGraph/draw.io, aimed at large enterprise diagrams), Reaflow (archived January 2026), react-diagrams/projectstorm (updated but a much smaller community), Drawnix/Plait (a newer React-capable whiteboard, small community, thin English docs), and Penpot (a self-hosted design app, not an embeddable library).

## How React Flow would fit our app

React Flow would become the single pan-and-zoom surface for the whole canvas. Our existing Craft.js frames become one custom node type; the new rectangles, diamonds, ellipses, parallelograms, and sticky notes become other node types, all on one shared surface instead of two canvases bolted together. React Flow owns panning, zooming, selection, dragging, and the connector lines; how each shape looks and behaves inside its own box is ours to build and style with our own Tailwind classes and SF2 tokens, so it matches our dark chrome instead of a demo. We would still need to build: the shape palette, in-shape text editing, the sticky-note look, a labeled-arrow connector component, undo/redo on top of React Flow's node and edge state, and a save/load step that writes the diagram into the same file as the rest of the document. A realistic first version (basic shapes, connectors with labels, save/load) is roughly 10 to 15 working days for one experienced engineer. The biggest uncertainty is how much today's frame canvas must change to share one viewport with React Flow; the work can split across two people, shapes and styling versus connectors and persistence, to shorten calendar time.

## Risks and a fallback

The main risk: we are committing to build the FigJam feel ourselves, so the first version will feel rougher than a finished product until polished, and that polish is real product-design and QA time, not just engineering time. A second risk is architectural: if today's frame canvas cannot be adapted to live inside React Flow's viewport without a large rewrite, the coexistence benefit shrinks and the estimate above grows. A third, smaller risk: React Flow has no built-in export, so PNG or SVG export needs an extra library (a documented pattern using html-to-image against the page). If this changes, the strongest fallback is tldraw: its license buys a finished shapes-and-connectors experience for far less build time, at the cost of a recurring fee and more work to make our frames live inside its canvas instead of the reverse. A lower-cost, higher-risk option worth a two-day spike is Quickdraw, a brand-new MIT alternative to tldraw that costs nothing but is too young to trust without hands-on testing.

## Building this from scratch

Building this with no library means writing our own pan-and-zoom coordinate system, hit-testing so clicks land on the right shape at any zoom level, drag and resize handles, and, hardest of all, connector math: finding the right point on a rectangle, diamond, or ellipse to attach a line, keeping that attachment correct as a shape moves or resizes, and routing the line so it does not cut through other shapes. That connector piece alone routinely costs experienced teams several weeks once labels and edge cases are added. A rough estimate for a bare-bones version is four to eight weeks, more than double the React Flow estimate above, for something still less robust than what React Flow already gives away free under a permissive license. It is worth building from scratch only if we needed interactions no library affords, which is not the case here.
