# A fourth Diagrams tab; icon-only tab strip

Date: 2026-09-14. Matt: "I did not want the diagramming elements dumped at the bottom of the components list. it should be it's own tab in that panel. also - instead of using words, let's use icons. Use an artist palette for design, lego block for elements, the existing diagramming icon for diagrams, and you can come up with an icon for prototyping that isn't a play button."

## 1. Decision

The right panel's tab strip becomes four tabs instead of three, each an icon-only button (no visible word), each with an `aria-label` carrying the real name for assistive tech and tooltips: **Design** (`lucide-react` `Palette`), **Prototype** (`Zap` — Figma's own Prototype tab uses a lightning-bolt mark; explicitly not a play/triangle shape, and distinct from the other three), **Elements** (`Blocks`), **Diagrams** (`Workflow` — the same icon that was on the removed top-bar "Diagram tool" button and is currently, confusingly, reused for Prototype; this reclaims it for its real meaning). Same four icons, same order, in both the expanded panel's tab strip and the minimized rail.

The Diagram group added earlier today to the bottom of the Elements list (spec `2026-09-13-diagrams-design.md` section 13) is removed from there and its content becomes the new Diagrams tab's own body instead: the same seven tool buttons (Rectangle, Rounded, Decision, Terminal, Text, Note, Connector) that arm a tool via `onSelectDiagramTool`, rendered as the tab's full content (comfortable spacing, not squeezed into a Craft-block-styled row list), with the same search-by-keyword and "i" docs support the Elements group had. Selecting a tool here or from the floating canvas-bottom palette (Shift+D) arms the same shared tool state; both stay.

## 2. Scope

- `lib/workbench/panel-store.ts`: `PanelMode` gains `'diagrams'`; `loadPanelMode`/`PANEL_MODES` updated; storage key and fallback (`'design'`) unchanged.
- `components/workbench/inspector/inspector.tsx`: `PANEL_LABEL` gets a `diagrams: 'Diagrams'` entry; `RAIL_ITEMS` gets a fourth `{ mode: 'diagrams', label: 'Diagrams', icon: Workflow }` entry (Prototype's existing entry changes its icon to `Zap`); the four `ToggleGroupItem`s render `<Icon className="size-4" aria-hidden />` with no text child, each `ToggleGroupItem` carrying `aria-label={PANEL_LABEL[mode]}` (Radix renders the group item as a real button, so this is the accessible name; wrap in a `Tooltip`/`TooltipContent` showing the word on hover, matching how `RailButton` already does this for the minimized rail); the body switch (`panelMode === 'components' ? <ComponentTray ... /> : ...`) gets a new `panelMode === 'diagrams'` branch rendering the diagram tool list (a new small component, e.g. `DiagramToolTray`, built from the same `DIAGRAM_TOOL_ITEMS`/`filterDiagramToolItems` already exported by `diagram-palette.tsx` and used by today's now-removed Elements-group code).
- `components/workbench/component-tray.tsx`: remove the Diagram group and its props (`diagramTool`, `onSelectDiagramTool`, `DIAGRAM_TRAY_ITEMS`, `filterDiagramToolItems` usage) entirely — Elements goes back to being Craft blocks only, unless a component or the Elements search box itself needs to keep pointing users at the new tab (see below).
- The "Modals are overlay frames: Frames chip → New overlay → Dialog" search hint (added with today's overlay work) is unaffected — it only fires when the Elements search comes up empty and stays in Elements' own scope.
- `lib/shortcuts.ts` + README: the D/P/E single-letter tab shortcuts need a fourth. Free single letters are scarce (T is diagram-text, V is pointer, C is comment); use **G** for Diagrams (mnemonic: "diaGram"; not otherwise bound) — `diagram-tab` `{ keys: ['G'], area: 'Panels', label: 'Diagrams tab' }`, gated exactly like D/P/E's existing entries (never while typing). `keyboard.tsx`'s `onSelectPanelTab` callback already takes a `PanelMode`, so this is one more `matchShortcut` case plus one more `if` in the same block that handles D/P/E today.
- Tests: every current D/P/E test in `inspector.test.tsx`/`workbench.test.tsx`/`topbar.test.tsx` (if any references the rail) needs its tab query updated from text (`getByRole('button', { name: 'Design' })` etc., which still works unchanged since `aria-label` keeps the word) to also assert the icon and the absence of visible text; new tests for the fourth Diagrams tab (renders the seven tools, `G` switches to it, arming a tool from here matches arming it from the floating palette, minimized-rail icon toggles to it); `panel-store.test.ts` gets `'diagrams'` round-trip and legacy-value-ignored cases; `lib/shortcuts.test.ts`'s drift test picks up the new row automatically.

## 3. Out of scope

Changing the floating bottom-centre Diagram palette (Shift+D) — it stays exactly as is, a second, canvas-adjacent way to reach the same tools. Reusing `Zap` or any new icon anywhere else in the app.
